Personal Project — MIT Licensed — October – December 2025

NetGuard

See the Wire, Stop the Threat. A real-time network intrusion detection system built in Python from raw sockets up — no Scapy, no libpcap. Captures live traffic via AF_PACKET raw sockets, hand-parses every layer (Ethernet → IPv4 → TCP/UDP/ICMP → DNS/HTTP), and runs it through a multi-detector pipeline for port scans, SYN floods, traffic anomalies, and IP reputation scoring — all surfaced in a live terminal dashboard.

Problem & Context

Most intrusion-detection tooling is a black box built on top of existing capture libraries. NetGuard was built to understand and implement that pipeline from first principles: parsing raw Ethernet frames with struct unpacking, reconstructing TCP state machines, and building the statistical and rule-based logic that decides what traffic is actually malicious.

Target users are students, security learners, and homelab/small-network operators who want a transparent, hackable IDS they can read top to bottom (~3,000 lines total) rather than configure through a black-box product. Validation was the hardest part of the build: proving that packet parsing and detection logic held up against real, messy traffic rather than a handful of clean test cases.

Writing a protocol parser directly against struct and raw sockets, rather than wrapping an existing capture library, forced a real understanding of Ethernet/IP/TCP framing, TCP flag semantics, and DNS message compression. Building four independent but coordinated detection strategies — signature-based scans, rate-based floods, statistical baselining, and a user-scriptable rule DSL — gave hands-on experience balancing detection sensitivity against false positives, plus practical work in stateful terminal UIs, YAML-driven configuration, and packaging a Linux-only, root-privileged tool for cross-platform development via Docker dev containers.

What It Does
  • 01Raw packet capture & parsing. Ethernet/IPv4/TCP/UDP/ICMP via manual struct unpacking; a DNS parser with compression-pointer resolution; basic HTTP request/response detection.
  • 02Port scan detection. SYN, FIN, XMAS, and full TCP-connect scans via windowed unique-port counting (ScanDetector).
  • 03SYN flood detection. Per-source rate tracking with severity scaling — WARNING → HIGH → CRITICAL.
  • 04Anomaly detection. TrafficBaseline learns a rolling 5-minute mean/std-dev baseline per protocol and flags statistical surges; separate detectors for port sweeps and connection floods.
  • 05IP reputation engine. File-backed blacklist/whitelist, suspicious-activity scoring with auto-promotion to "malicious" past a threshold, JSON state persistence across runs.
  • 06Custom rules engine. YAML-defined rules with compound conditions (TCP flags, ports, packet size, time windows), enabled/disabled toggling and hot-reload at runtime without restarting capture.
  • 07Alerting. JSONL alert log (last 1000), severity-coded terminal output, desktop notifications via notify-send with cooldown.
  • 08Rich TUI dashboard. Live stats/alerts/connections/top-talkers/packet-feed panels with keyboard controls — pause/resume, protocol filter cycling, PCAP export.
  • 09CLI mode. A 24-option interactive menu for offline analysis of a captured batch — search by IP/port/protocol, DNS query history, reputation lookups, rule management.
  • 10Cross-platform dev container. Docker-based VS Code Dev Container so the Linux-only raw-socket capture runs unmodified on macOS/Windows.
Architecture

main.py switches between TUI and CLI mode via argparse. Captured packets flow through a single pipeline: packet.py parses raw bytes into a Packet object (Ethernet → IP → transport → DNS/HTTP); this feeds threat_detection.py (ScanDetector, SYNFloodDetector) and anomaly_detection.py (TrafficBaseline, PortSweepDetector, ConnectionFloodDetector) in parallel, alongside ip.py's reputation scoring and rule_engine.py's user-defined YAML rules.

Detector hits become alerts consumed by alert_manager.py (logging, notifications) and rendered live by interface.py's Rich-based TUI, while analyzer.py maintains connection/DNS state and net_statistics.py tracks protocol-level counters. config_manager.py provides YAML-backed settings with deep-merge defaults and dot-notation access throughout.

Note
Note: this project requires raw-socket access on Linux (AF_PACKET) and root privileges to run, so it cannot be hosted as a public live demo — the dashboard screenshot above and the GitHub repo are the right substitute.
